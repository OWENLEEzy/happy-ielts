# 狗狗角色化 UI 美化设计

## 目标

在不改变当前紫色课程主题的前提下，围绕狗狗图片建立一套更清晰的界面语言，并清理已经废弃的暗黑主题残留代码。

狗狗图片不是普通装饰素材，而是产品识别的一部分。本次设计保留随机 URL 机制，但随机必须严格发生在正确的角色池内，不能再出现角色语义漂移。

本次设计有两个直接结果：

1. 保留随机图片机制，但改为按角色池随机。
2. 提升头像和提示卡的一致性，并移除未使用的暗黑 token / mixin。

## 已确认的角色系统

项目已经有明确的三类图片资源：

- `teacher`：金毛，代表老师角色
- `user`：小白，代表用户角色
- `relationship`：合照，代表“我们一起学”的关系角色

这三类是语义角色，不是页面上的随意换图。

### 角色含义

- `teacher` 负责引导、讲解、反馈、提醒和教学存在感。
- `user` 负责表达“我”的输入、状态、回答和学习进度。
- `relationship` 负责表达欢迎、陪伴、共同成长、解锁和庆祝等品牌关系感。

## 非目标

- 不引入第二套视觉主题。
- 不替换现有紫色课程色板。
- 不取消随机图片机制。
- 不做整站重设计。
- 不顺手清理无关的通用 `dark:` 兼容类。

## 当前问题

### 1. 角色语义还没有真正落到页面

常量层面已经分出了老师、小白、合照三组图片，但页面调用仍有漂移。有些页面直接使用老师图片 helper，即使这个页面更适合关系角色或用户角色。

### 2. 头像视觉语言分散

目前每个页面都在各自处理头像尺寸、边框、阴影和强调方式，导致整体像是几套局部样式拼在一起，而不是一个统一产品。

### 3. 暗黑主题残留已经失效

前端仍保留一组旧的 General Learning 暗黑 token 和 mixin，但它们已经不在当前 UI 生效链路中，只会增加维护噪音。

## 核心原则

### 随机是合理的，但只能在角色池内部随机

本次设计明确保留随机 URL 机制，但随机必须服从语义边界：

- 老师位只能从老师池随机
- 用户位只能从用户池随机
- 关系位只能从合照池随机

红线只有一条：不能把小白当老师，也不能把合照当成单人导师头像。

### 一页一个主角色锚点

大多数页面只保留一个主要的狗狗出场位。例外是聊天型界面，这类页面允许老师和用户成对出现。

### 狗狗是品牌大使，不是贴纸

狗狗图片应该出现在有意义的位置，并且用稳定的视觉语法承载品牌记忆点，而不是无差别地点缀每一屏。

## 页面分工

### 关系狗（合照）

适用场景：

- 首页 hero / 产品入口
- 欢迎页或品牌陪伴感更强的入口位
- 解锁、庆祝、完成等高情绪节点
- 创建项目成功、进入新阶段等“我们一起前进”的场景
- 合适的鼓励型空状态

### 老师狗（金毛）

适用场景：

- 英语 onboarding
- 通用学习 onboarding
- 备课中 / loading / planner 状态
- 阅读提示卡
- lesson 对话与自由问答
- 写作反馈建议卡
- 其他明确属于教学或指导的界面

### 用户狗（小白）

适用场景：

- 用户侧聊天气泡
- 个人状态卡、学习进度卡
- 提交后状态、个人视角卡片
- 其他强调“这是我”的界面位置

## 视觉系统

### 统一头像 API

实现层应该把头像渲染收口到一个语义化 helper 或组件上。页面传入的是角色，不是某一张具体图片 URL。

建议输入维度：

- `role`: `teacher | user | relationship`
- `size`: 预设尺寸或像素值
- `emphasis`: 用于区分 hero、卡片、inline 等不同强调层级
- `alt`: 可选文案

内部由该 helper / 组件从正确角色池里随机选图。

### 按角色区分的视觉语法

#### 老师狗

- 暖金感边框
- 比用户头像更明显一点的 halo / glow
- 整体气质偏导师、提示、引导

#### 用户狗

- 更干净、更轻的浅白紫边框
- 更克制的阴影
- 整体气质偏“我自己”的学习状态

#### 关系狗

- 更完整的 halo 或徽章感容器
- 在品牌入口和庆祝时拥有最高强调级
- 表达的是关系和陪伴，不是权威角色

### 尺寸梯度

统一尺寸节奏：

- hero / 主视觉锚点：约 `72-88px`
- 卡片 / 提示位：约 `36-48px`
- 对话 / inline：约 `24-32px`

除非布局确有需要，否则不要继续出现大量随意尺寸。

## 本次实施范围

### 核心实现

1. 引入一个统一的狗狗角色头像 helper 或组件。
2. 页面从“直接取某类 URL”逐步改成“按角色取图”。
3. 首页主头像切到 `relationship`。
4. 保留教学链路中的老师角色。
5. 在合适的用户侧位置补上 `user` 角色。
6. 删除未使用的暗黑主题 SCSS token 和 mixin。

### 本轮建议改动页面

#### 首页

- 主头像从老师狗改成关系狗
- 加强头像容器，让它更像品牌入口，而不是课程子页面的头像角标

#### 英语 onboarding

- 保留老师狗作为主引导
- 如果版面不乱，用户消息侧补用户狗，形成成对对话语义

#### 通用学习 onboarding

- 同样保留老师狗主导
- 条件允许时补用户侧身份

#### 备课中

- 继续使用老师狗
- 统一头像容器和阴影，和其余页面保持一致

#### 阅读提示卡与反馈建议卡

- 保留老师狗
- 统一头像框、间距和强调方式

#### 完成、解锁、评分卡

- 凡是表达“我们一起进步”或庆祝感更强的界面，优先使用关系狗

## 暗黑 token 清理

从以下文件中移除未使用的旧暗黑主题残留：

- `frontend/styles/_tokens.scss`
- `frontend/styles/_mixins.scss`

具体移除内容：

- 所有 `$gl-*` 变量
- `gl-button`
- `gl-card`
- `gl-input`

本次不把清理扩展成更大的主题重构。

## 安全约束

- 如果个别页面仍需要直接访问 URL，必须让角色语义在局部代码中清晰可见。
- 如果角色缺失，应回退到安全默认值，但不能偷偷把一种角色替换成另一种角色。
- 清理暗黑残留时，只删未使用代码，不改当前紫色主题 token。

## 验证

### 功能验证

- 确认每个角色只会从自己的图片池中取图
- 确认首页改用关系狗
- 确认教学页面继续使用老师狗
- 确认新增的用户侧位置使用小白池
- 确认删掉暗黑 token / mixin 后，没有活动页面仍依赖它们

### 视觉验证

- 对比首页、onboarding、备课中、阅读提示卡、反馈页、lesson 对话中的头像表现是否统一
- 确认新的头像样式仍和当前紫色主题协调
- 确认狗狗的存在感稳定，不会忽强忽弱或显得到处乱贴

## 本次设计已确认的决策

- 随机 URL 保留
- 分类是第一原则
- 问题不在随机，而在角色混用
- 整体仍保留当前紫色课程主题
- 本轮目标是提升一致性，不是整站重设计

## 总结

这次改动的目标，是让狗狗图片从“有趣素材”升级成“明确的产品语言”。

最终界面应该满足：

- 金毛负责教
- 小白负责代表用户
- 合照负责表达关系和品牌陪伴

在这个前提下继续保留随机图片机制，再配合统一的头像视觉系统和暗黑残留清理，界面会更清楚、更有记忆点，也更像一个完整产品，而不是若干局部页面的拼接。
